# C2 补强证据：F1/F2 陈述保真度的可复现检查

**动机**：C2 的 AI 初评（evaluation_id `eval-20260929172001-0035450f`，89/100）明确建议——「补齐编译验证并沉淀 F1 的可复现检查」。编译验证已由仓库内 CI 流水线补上（另见 `mini-/.github/workflows/build-paper.yml`）；本目录落实后半句。

**它补的是哪一块**：论文把「保真度关卡」列为退休 F1（陈述漂移/错形式化）与 F2（量词或逆命题错误）的唯一机制，但原文只有叙述、没有可跑的实现与量化。本目录给出一个**机械检查器 + 手工探针集 + 实跑结果**。

---

## 方法

- **检查器**（`run-probe.py`）：只抽取四类表面特征——条件原子（24 词表：nonzero / continuous / bounded / finite / compact / prime …）、量词类（全称 / 存在）、句内数值集合、严格不等号（`<` `>`）计数；对「意图陈述」与「形式化陈述」各抽一次并比对。量词类不同 → 判 F2；其余差异 → 判 F1；无差异 → 不报警。
- **探针集**（`probe-cases.json`）：22 例配对，**16 例漂移 + 6 例忠实对照**，覆盖四类表面漂移（侧条件缺失 4、界值改变 3、严格性改变 3、量词错位 4）与两类词面不可见的语义漂移（逆命题/方向互换 2）。真值标签由作者预先标注，检查器不可见。

## 关键发现

1. **F1 类漂移可完全机械化检出**：侧条件缺失、界值改变、严格性改变，三类各 10/10 命中，且 0 误报。这直接支持论文「保真度关卡可以部分自动化」的主张，并把"可自动化到什么程度"从叙述变成了可复算的数字。
2. **F2 类分裂为两半**：量词错位（∀↔∃ 改写措辞）4/4 全中；**逆命题/方向互换 2/2 全漏**——因为两者的词面特征集合完全相同（如"可微 ⇒ 连续"与"连续 ⇒ 可微"）。这正是论文主张「保真度关卡必须由未参与形式化的第三方承担」的**实证依据**：纯表面比对存在结构性盲区。
3. **误报为零**说明该检查可直接接入流水线而不产生噪声负担——但它只覆盖 F1/F2 的表层部分，F3–F10 不在此检查范围内。

## 限制（如实声明）

- 探针集为**手工构建、非随机抽样**，存在构造偏差；上述比例描述的是"该检查器在该探针集上"的表现，不是总体估计。
- 检查器词表固定（24 项），**词表之外的语义漂移不可见**，非语法级/非语义等价判定。
- 数值特征取"句内全部数字的集合"，可能含与论断无关的数字噪声。
- 全程无 Lean / kernel 参与，属**文本层**检查，不构成形式验证。
