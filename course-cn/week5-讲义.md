## 探索起始应用
一个最小化的全栈起始应用。
- 带 SQLite（SQLAlchemy）的 FastAPI 后端
- 静态前端（不需要 Node 工具链）
- 最简测试（pytest）
- 提交前钩子（black + ruff）
- 用于练习智能体驱动工作流的任务

请把这个应用当作试验场，用来试验你构建的 Warp 自动化。

### 目录结构

```
backend/                # FastAPI 应用
frontend/               # 由 FastAPI 提供的静态界面
data/                   # SQLite 数据库 + 种子数据
docs/                   # 面向智能体驱动工作流的任务
```

## 第一部分：构建你的自动化（选择 2 个或更多）
从 `week5/docs/TASKS.md` 中挑选任务来实现。你的实现必须以下面两种方式用到 Warp（详见后文）：

- A) 使用 Warp Drive 功能——例如保存的提示词、规则或 MCP 服务器。
- (B) 在 Warp 内结合多智能体工作流。

请把改动保持在 `week5/` 内的后端、前端、逻辑或测试范围内。
对每个选中的任务，注明其难度级别。

### A) Warp Drive 的保存提示词、规则与 MCP 服务器（必需：至少一个）
创建一到多个可共享的 Warp Drive 提示词、规则或 MCP 服务器集成，并针对本仓库做定制。示例：
- 带覆盖率和易失败测试重跑的测试运行器
- 文档同步：由 `/openapi.json` 生成/更新 `docs/API.md`，列出路由变更
- 重构支撑：重命名模块、更新导入、运行静态检查/测试
- 发布助手：提升版本号、运行检查、准备变更日志片段
- 集成 Git MCP 服务器，让 Warp 自主与 Git 交互（创建分支、提交、PR 说明等）

>*提示：让工作流保持聚焦、支持传参、做到幂等，并尽量采用无头/非交互式步骤。*

### B) Warp 中的多智能体工作流（必需：至少一个）
运行一次多智能体会话，让不同 Warp 标签页中的各个智能体并发处理彼此独立的任务。
- 用并发智能体在多个 Warp 标签页中完成 `TASKS.md` 里的多个自包含任务。挑战：你最多能让多少个智能体同时工作？

>*提示：[git worktree](https://git-scm.com/docs/git-worktree) 在这里可能有用，可以避免各智能体的改动互相覆盖。*
