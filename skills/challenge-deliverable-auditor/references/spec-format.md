# 平台要求清单的模式语法

## 清单原文长什么样

平台把"要交什么"存成一个**逗号分隔的模糊模式串**，例如：

```
*skill说明*,*.skill,*教学说明*,*demo*,*AI日志*
```

读取位置（优先级从高到低）：

1. `challenge.json` 的 `required_deliverables`（与 `deliverables` 通常相同）
2. `challenge.json` 的 `deliverables`
3. `get-challenge` 返回体里的交付物字段

**原样复制**，不要"顺手规范化"。

## 判定规则（本技能实现）

1. **切分**：按 `,` `;` `，` `；` 切分，去空格、去引号、转小写；空段丢弃。
2. **通配**：模式含 `*` 或 `?` 时视为 glob（大小写不敏感）。
   - `*.skill` → 命中任何以 `.skill` 结尾的文件名；
   - `*demo*` → 命中任何含 `demo` 的文件名；
   - glob 未命中时，再做一次"去掉通配符后的子串包含"兜底 → 记为 `PASS_FUZZY`。
3. **字面**：模式不含通配符时，先要求**完全相等**（大小写不敏感）；
   - 无相等项但有子串命中 → `PASS_FUZZY`（提示改名对齐）；
   - 全无 → `MISSING`。
4. **空文件**：有命中但所有命中文件都小于 `--min-bytes` → `EMPTY`。
   `EMPTY` 与 `MISSING` 在平台侧通常**同罚**（都算交付物缺失），所以二者都使 `ready=false`。

## 三个高频踩坑（真实发生在 C1–C4 提交过程中）

### 1. `>` 重定向写出 0 字节文件

Windows PowerShell 下把扩展名不明确的输出重定向到 `.txt`/`.md`，
或对含中文的输出流做管道，可能落出一个 **0 字节文件**：文件列表里看得见，
提交后判缺失。**自检方法**：审计器的 `risks[]` 会直接把它标成 `error` 级。

### 2. 文件名与模式关键词不同字

| 平台模式 | 学生常写 | 结果 |
|----------|----------|------|
| `*skill说明*` | `技能说明.md` | MISSING（"说明"在，"skill说明"不在） |
| `*教学说明*` | `教学指南.md` | MISSING |
| `*AI日志*` | `ai-log.md` | MISSING（`ai` 与 `AI日志` 不同） |
| `*.skill` | `my-skill.zip` | MISSING（扩展名必须 `.skill`） |

**解法**：文件名里**原样包含**模式中的非通配关键词，如
`C4-skill说明.md`、`C4-教学说明.md`、`C4-AI日志.md`、`my-skill.skill`。

### 3. 交付物放在子目录

清单模式匹配的是**文件名**，不是路径。文件放在 `deliverables/` 里通常仍能命中
（本技能递归扫描），但平台侧若只扫根目录就会漏。**稳妥做法**：核心交付物放提交根目录。

## 与平台 `check-deliverables` 的关系

| | 本技能（本地预检） | 平台 check-deliverables |
|---|---|---|
| 联网 | 不需要 | 需要 |
| 依据 | 你粘贴的清单原文 | 平台库里的清单 |
| 能力 | 逐项判定 + 字节数 + 整改清单 | 权威判定 |
| 定位 | **先跑，把问题提前暴露** | 提交前的权威复核 |

推荐顺序：`audit.py`（本地） → `check-deliverables`（平台） → 展示摘要 → 学生确认 → `submit-project`。
